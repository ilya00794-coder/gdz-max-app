# Эталонная база решений — формат файлов

Здесь лежат **собственные решения автора базы**: он решает задачи из учебников
сам, вручную. Это его текст — он в git, версионируется и вычитывается как код.

## Что сюда НЕЛЬЗЯ класть (правило проекта №1)

- **Тексты условий из учебников** — поля «условие» в формате нет намеренно,
  задача идентифицируется только ссылкой: учебник + номер.
- Тексты чужих готовых решебников (ГДЗ) в любом виде.
- Сканы/фото страниц учебников.

## Формат: один Markdown-файл = один учебник одного издания

```markdown
# Учебник: Виленкин Математика 5
издание: 2023, Просвещение
класс: 5
предмет: Математика

## 1241а
тема: уравнения
ответ: x = 6
sympy: 6

1. Переносим 9 в правую часть: 3x = 27 − 9 = 18
2. Делим обе части на 3: x = 18 / 3 = 6

## 1241б
ответ: x = 2; x = 3
sympy: 2; 3
```

### Шапка файла (все четыре строки обязательны)

- `# Учебник:` — название **в той форме, в какой его распознаёт vision с фото**
  («Виленкин Математика 5», не библиографическая запись). Регистр не важен,
  ключ нормализуется при импорте.
- `издание:` — год и/или издательство («2023, Просвещение»). Обязательно:
  у Виленкина нумерация задач менялась между изданиями, эталон из чужого
  издания хуже отсутствия эталона. Одна книга в двух изданиях = два файла.
- `класс:` — 1–11.
- `предмет:` — как на экране выбора в приложении («Математика», «Алгебра»).

### Запись задачи

- `## <номер>` — номер задания как в учебнике: `1241`, `389а`, `К-5 В1 №2`.
- `тема:` — необязательно.
- `ответ:` — обязательно, как показал бы человек: «x = 6», «12 км/ч».
- `sympy:` — ответ в форме для машинной сверки: только значения корней/чисел,
  несколько — через `;` («6», «2; 3», «0,4»). Для задач, где машинная сверка
  невозможна (доказательства, построения), строку можно опустить — эталон
  сохранится, но в сверке участвовать не будет (v1 — только точные науки).
- Нумерованный список — шаги решения **своими словами**. Необязателен:
  запись «только ответ» тоже ценна.

## Как импортировать

`npm run import-reference <файл>` (импортёр — шаг 2, в разработке).
Импорт идемпотентен: файл можно править и перезаливать, записи обновятся
по ключу (учебник, класс, предмет, номер, издание).

## Образец

`example.md` — вымышленный демо-файл с форматом. Задачи и решения в нём —
собственные примеры проекта, ни из какого реального учебника не взяты.
В прод-базу его не импортировать.
