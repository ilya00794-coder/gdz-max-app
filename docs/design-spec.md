# Дизайн-эталон — стиль «Чистый / светлый» (направление A)

Утверждён пользователем как единый визуальный стиль приложения. Заменяет прежний
тёмно-зелёный «доска + маркеры». Это источник правды для переверстки всех экранов.

## Философия
Спокойный, светлый, «как банковское приложение / iOS-настройки». Много воздуха,
один акцентный цвет, минимум декора. Никаких рукописных шрифтов, никаких тёмных фонов,
никаких маркерных полос. Приложение должно выглядеть «родно» внутри MAX (MAX UI —
светлая нативная система), а не как отдельный чужеродный виджет.

## Подача решения
ВСЁ решение — одним прокручиваемым списком сверху вниз. НЕ свайп по одному шагу (сторис/рилс
убираются полностью). Шаги пронумерованы кружками, идут вертикально, ответ — внизу отдельным
выделенным блоком.

## Цветовые токены
- Фон страницы: #FFFFFF (белый), контейнер-подложка: очень светлый серый (#F1EFE8)
- Основной текст: #2C2C2A (почти чёрный, не чистый чёрный)
- Вторичный текст: #444441
- Приглушённый текст / подписи: #888780
- Акцент (единственный): синий #185FA5, светлая заливка акцента #E6F1FB, тёмный текст на
  заливке #04234F
- Формулы/моноширинный акцент: #185FA5
- Успех/«проверено»: #0F6E56 (зелёный текст), иконка ti-circle-check
- Ошибка/«сообщить»: #993C1D (приглушённый красно-коричневый), иконка ti-flag
- Границы: тонкие 0.5px, светло-серые

## Типографика
- Системный шрифт (San Francisco на iOS, Roboto на Android) — НЕ Caveat, НЕ рукописные
- Заголовок экрана: 15px, вес 500
- Заголовок шага: 15px, вес 500, цвет #2C2C2A
- Тело шага: 14px, line-height 1.6, цвет #444441
- Ответ (крупно): 24px, вес 500, моноширинный для самой формулы
- Подписи/метки: 12–13px, при необходимости uppercase с letter-spacing 0.03em
- Только два веса: 400 обычный, 500 полужирный. Не использовать 600/700.
- Регистр предложений (Sentence case), не Title Case, не ВЕРХНИЙ РЕГИСТР

## Компоненты
- Карточки: белый фон, скругление 12px, граница 0.5px
- Кнопки: скругление 10px, белый фон, граница 0.5px, текст 14px
- Кружок номера шага: 26px диаметр, заливка #E6F1FB, цифра #185FA5, вес 500
- Блок ответа: заливка #E6F1FB, скругление 12px, метка «Ответ» сверху, крупное значение,
  строка верификации снизу
- Прогресс/индикаторы больше не нужны (список вместо свайпа), полосы прогресса убрать

## Экран решения (эталонная структура, утверждён макет)
1. Шапка: [← назад] · «Решение» · краткое условие справа, снизу тонкая граница
2. Список шагов: кружок-номер + (заголовок шага, тело шага), вертикально, зазор ~18px
3. Блок ответа: светло-синий, «ОТВЕТ» (метка) → значение (крупно, моно) → строка
   «✓ Ответ проверен вычислением» (или честная пометка «не проверено», см. правило skill)
4. Нижние кнопки: «Новая задача» + «Ошибка в ответе» (флаг). Кнопка ошибки — на будущее,
   требует backend-эндпоинта приёма жалоб (см. backlog «Кнопка ответ неверный»)

## Логотип и брендинг
Название бота: «Домашка» (собственный бренд), «в MAX» / «•max» — указание платформы,
НЕ часть собственного знака (MAX — чужой товарный знак VK, не делать его частью своего лого).

Файлы (положить в webapp/assets/):
- logo-header.svg — горизонтальный знак «домашка•max» (синий #185FA5 + мятная •max #8FD0C0
  на прозрачном/белом). Для шапки экранов setup/capture/confirm/solution.
- logo-icon.svg — квадратная иконка: синий скруглённый квадрат, белая «д» + мятная «•max».
  Для favicon (закрывает пункт бэклога про 404 favicon), аватарки бота, заставки.

Шрифт логотипа — Unbounded (переведён в контуры внутри SVG, подключать веб-шрифт не нужно).
В остальном интерфейсе — системный шрифт, как указано в типографике выше (Unbounded только
в самом логотипе, не в текстах интерфейса).

## Что распространить на остальные экраны (setup / capture / confirm)
Те же токены и типографика. Экран выбора класса/предмета — светлые чипы вместо тёмных
«наклеек», экран съёмки — светлая рамка кадра, экран подтверждения — светлое поле ввода.
Формулы везде через KaTeX (уже подключён), не сырой LaTeX.

## Важно сохранить из текущей логики (НЕ ломать при переверстке)
- KaTeX-отрисовка формул
- Пометка верификации (verified true/false) — честная, без выдуманных уровней уверенности
- Отсутствие мок-fallback (при ошибке — честное сообщение, не чужое решение)
- Определение MAX Bridge / режимов (max/blocked/preview)
- Логика активности кнопок по состоянию
