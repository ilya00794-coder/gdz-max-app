# Бэклог идей — мини-приложение MAX для учеников и родителей

## MVP (первая версия)
- [ ] Проверка домашней работы по фото тетради (1 или несколько фото)
- [ ] Поиск задачи из учебника по фото/тексту + решение с учётом класса обучения
- [ ] Точная идентификация учебника (класс → предмет → учебник → номер задания), т.к. номера задач различаются между изданиями
- [ ] Профиль ученика: класс, предметы
- [ ] Базовый родительский просмотр (что делал ребёнок, какие задачи решал)

## Точность решений (ключевое требование — уровень ГДЗ)
- [ ] Решение «с нуля» на основе условия из фото/текста пользователя — НЕ через сбор и хранение чужих учебников и ГДЗ целиком (юридически рискованно)
- [ ] Собственная библиотека методических паттернов по темам школьной программы («как решать задачи на движение» и т.п.) — общие методы, а не чужие произведения
- [ ] Собственная верифицированная база ответов, растущая органически из решений самой системы (не скачанная с чужих ГДЗ-сайтов)
- [ ] Интеграция с Wolfram Alpha API (и/или SymPy бесплатно) для проверки математических/физических ответов
- [ ] Генерация решения несколькими способами и сверка совпадения (сигнал уверенности)
- [ ] Кнопка «ответ неверный» → отправка на ручную проверку экспертом → исправление базы
- [ ] Уровень объяснения должен соответствовать пройденным на момент задания методам по программе класса
- [ ] Купленные ГДЗ/учебники — использовать только как внутренний эталон для QA (сверка финального ответа), НЕ копировать текст объяснений в продукт
- [ ] Показывать пользователю распознанный текст условия/решения ДО выдачи ответа с возможностью исправить (защита от ошибок OCR)

## Кэширование и оптимизация затрат на AI
- [ ] Канонический ключ задачи: учебник + номер задания (если распознаётся на фото), иначе — нормализованный хэш текста условия
- [ ] Проверка кэша перед обращением к AI: найдено → мгновенный бесплатный ответ; не найдено → полный AI-пайплайн → сохранение результата в базу
- [ ] Разделение моделей по задачам: дешёвая/быстрая — для OCR и извлечения условия, дорогая/точная — только для решения новых (некэшированных) задач

## Цикл самоулучшения точности

- [ ] Логирование расхождений: тема, класс, тип ошибки (OCR/метод/вычисление)
- [ ] Донастройка промптов/логики решения по проблемным темам на основе логов
- [ ] Дообучение на собственных проверенных решениях (не на тексте чужих ГДЗ) по мере накопления верифицированной базы
- [ ] Дашборд точности по предмету/классу/теме для приоритизации доработок

## Открытые вопросы / риски (требуют решения до старта разработки)
- **Юрлицо/ИП/самозанятый**: подключение к платформе «MAX для партнёров» и публикация мини-приложения доступны только резидентам РФ с таким статусом — нужно определить, на кого регистрировать бота
- **Авторские права на учебники**: нельзя просто сканировать и распространять содержимое учебников целиком — нужна либо собственная база задач, либо генерация аналогичных задач, либо лицензия от издательства
- **Массовый сбор всех учебников и всех ГДЗ в свою базу — недопустим**: это оптовое копирование чужих охраняемых произведений (и учебников, и решебников). Вместо этого — решать задачи самостоятельно (по фото/тексту конкретного пользователя) и накапливать свою верифицированную базу органически, а не скачивать чужой контент
- **Копирование чужих ГДЗ-сайтов недопустимо**: решения нужно генерировать/проверять самостоятельно, а не копировать тексты с существующих решебников — у издательств (напр. «Просвещение») были прецеденты претензий к сайтам-решебникам
- **152-ФЗ и данные детей**: фото тетрадей — персональные данные несовершеннолетних; нужны политика конфиденциальности, согласие родителя, минимизация хранения фото (например, удалять после обработки)
- **Точность распознавания почерка**: особенно у младших классов — нужен fallback на ручной ввод текста, если OCR не справился
- **Хостинг**: мини-приложение требует HTTPS-хостинга статики (VK Cloud / GitHub Pages / Yandex Cloud) + отдельный бэкенд-сервер для AI-обработки.
  С 30.08.2026 аргумент стал жёстче: экран настройки берёт список предметов
  с бэкенда (GET /api/subjects), при недоступном туннеле пользователь не
  увидит предметов вообще — без постоянного сервера приложение мертво
  с первого экрана

## Пробелы промпта, найденные замером prompt-gaps (фиксация 30.08.2026, чинить после замера)
Источник: слепое судейство решений по (класс, предмет), начиная с 1 класса.
Оценка судьи субъективна (модель), но пункты ниже повторялись систематически.

1. [ ] **ПРИОРИТЕТ: LaTeX-доллары вокруг кириллицы в нематематических предметах**
       («$а$», «$4$ буквы» в решениях по русскому языку). Это баг, видимый
       пользователю: на фронте KaTeX отрендерит это как формулу с математическим
       начертанием. Чинится промптом solver (формулы только для математики).
2. [ ] Математический шаблон шагов («что дано», «проверка», нумерованные шаги)
       навязан устным предметам — русскому, чтению. Схема шагов в промпте
       писана под вычисления.
3. [ ] Ответ прячется в конец: для младших классов и устных предметов нужен
       короткий ответ сначала, потом объяснение.
4. [ ] Правило не называется явно («сколько гласных — столько слогов»,
       «на N больше = столько же и ещё N») — применяется молча, ученику
       не на что опереться в следующей задаче.

6. [ ] Нет школьного оформления записи: краткая запись условия
       («Было — Вышли — Вошли»), образец тетрадной записи («дуб — дубы (б)»,
       «Ответ: 18 см»), решение «1) … 2) …». Домашку сдают тетрадью.
7. [ ] Английский: нет произношения и чтения слов (в началке это половина
       предмета; у Opus вдобавок ошибка в транскрипции «three» → «фри»).
8. [ ] Литература: нет опоры на текст — цитат и ключевых слов произведения
       («владычица морская»), которые ждёт учитель.

9. [ ] Гуманитарная инверсия: перегруз фактами сверх вопроса (история 5 кл.:
       в ответ про клинопись приезжают Хаммурапи и Гильгамеш; в довесках —
       фактический дрейф: плуг рядом с мотыгой, кузнечное дело при земледелии).
10. [ ] Не используются опорные слова учебника: «дар Нила», «присваивающее →
       производящее»; решение говорит «Месопотамия», когда в условии
       «Междуречье». Учитель ждёт формулировок учебника.

Отдельно — НЕ дефект промпта, а продуктовая задача:
- [ ] **Наглядная опора** (числовой луч, счётные палочки, «домики» состава
      числа, дуги слогов, звуковые схемы) — самый частый пробел по мнению
      судьи (~20 упоминаний на 30 разборов 1 класса), но промптом не чинится:
      требует отрисовки схем на фронте (SVG/канвас или текстовые псевдосхемы).
      Аргументы копятся: (1) замер 8 класса — доказательства про диагонали
      четырёхугольников нечитаемы в текстовом канале (тройные обозначения
      углов ∠OAB/∠OCD судья назвал «трудночитаемыми без чертежа»; словесную
      расшифровку решили НЕ добавлять — с чертежом она станет шумом);
      (2) место под наблюдение 9 класса: алгебра-график и окружность бьют
      в ту же границу — дополнить после прогона.

## Наблюдения о моделях (из замера prompt-gaps, 2 класс) — НЕ пробелы промпта
- **Haiku ошибается на ТОНКОЙ фактуре, а не «на гуманитарных вообще»**
  (уточнено после 5 класса): промахи — точные формулировки правил (чк-чн
  раздуто до «после ч и щ ь не пишется»), детали сюжета (лесенка желаний
  в «Сказке о рыбаке и рыбке»), морфемный разбор («подснежник» с окончанием
  -ик). На фактах уровня учебника 5 класса (история/география/биология)
  не уступает Opus — 40/40. Вывод для будущей маршрутизации моделей:
  граница проходит по «есть ли объективный арбитр» (SymPy/эталон) и по
  требуемой точности формулировок, а не по предмету или сложности задачи.
- **РИСК: ложное обобщение правила опаснее неверного ответа** — неверный ответ
  ученик заметит по несовпадению, а неправильное правило унесёт дальше и будет
  применять к другим словам/задачам. Учесть при любом решении о дешёвой модели
  на гуманитарных предметах.

## Ограничение curriculum-слоя (замечено на 2 классе, пока не чинить)
- [ ] Белый список методов работает на уровне КЛАССА, но не ТЕМЫ: столбик

## Ход замера prompt-gaps (обновлено 30.08.2026)
- 1–3 классы пройдены: 8 категорий пробелов (см. список выше), на 3 классе

- 4 и 6 классы пропущены ОСОЗНАННО (состав предметов повторяет соседние

- План дальше: 5 класс (только новые предметы: история, география, биология

  информатика; особое внимание: понятность геометрии БЕЗ чертежа и единицы
  измерения/размерность в физике) → дальше по обстановке.

## РИСК: брак генерации текста — смешение алфавитов и битые слова (НЕ пробел промпта)
Чинится не промптом, а пост-проверкой текста перед отдачей пользователю.
Пока только фиксация, не чинить.

Примеры из замера prompt-gaps (решения, которые увидел бы ученик):
- Opus, 5 класс, история: «самой長 длинной» (CJK-иероглиф внутри русского
  слова), «egyptянам» (латиница в слове), «перенялиьвавилоняне» (склейка).
- Haiku, 5 класс, история: «перевол», «с больше запасами» (аграмматизмы).
- Haiku, 2 класс, литчтение: «круглый и весёлый булочка».

Частота по классам (упоминания судьёй в 40 разборах на класс):
1 класс — 1 (haiku), 2 класс — 1 (haiku), 3 класс — 0, 5 класс — 5 (обе
модели). Похоже, провоцируется длинными русскоязычными гуманитарными
ответами. Возможное направление починки: дешёвый пост-проход проверки
текста (регэксп на смешение алфавитов + LLM-вычитка) перед показом.

## Слепое пятно наборов: один тип источника (наблюдение 31.08.2026)
Баг «задача с доски отклоняется как „не из учебника“» нашёлся ОБЫЧНЫМ
ИСПОЛЬЗОВАНИЕМ, а не замером и не канарейкой — и ни один наш замер его
бы не поймал: во всех наборах (ocr-eval, prompt-gaps, model-compare)
условия либо печатные из учебников, либо текстовые. Фото доски, карточки,
экрана, диктовки в наборах нет вовсе.
**Вывод для будущих замеров: наборы собраны из одного типа источника —
это слепое пятно. При следующем замере добавить нетипичные источники:
доска, карточка, экран, диктовка.** Родственен «уроку догонки»
(prompt-gaps-report): новые классы дефектов приходят из непохожести
природы задания, а не из трудности.

## Оцифровка физики в curriculum — отложена по пробе (01.09.2026)
Находка: физика (и химия, информатика) живут без белого списка методов —
buildProgramBlock подставляет мягкую заглушку «ориентируйся на типичный
уровень класса». Проба-провокация (9 задач: физика 7–8 «на вырост» +
алгебра-контроль с白 списком, ~$0.35): **9/9 чисто, нарушений нет**.

Два факта из пробы (важнее самой пробы):
- Модель не просто избегает старших методов — она НАХОДИТ ОБХОДНЫЕ ПУТИ
  уровня класса: средняя скорость вместо кинематики 9 кл., средняя сила
  вместо интеграла. Это сознательный выбор уровня, не неспособность.
- Вывод «мягкие формулировки игнорируются» оказался НЕ универсальным:
  он про предметные требования к оформлению, а не про уровень сложности,
  где у модели есть собственное представление об уместном.

Известная граница (не дефект): h = g·t²/2 у 8-класса — серая зона стыка
программ (свободное падение в большинстве УМК — 9 класс); без
оцифрованного списка граница определяется представлением модели
о «типичном уровне», размытым на стыках классов.

Триггеры возврата к оцифровке:
1) жалоба на метод не по программе или замер, показавший нарушение;
2) оцифровка понадобится для чего-то ещё (например, карты типов задач
   из раздела ниже) — тогда ограничение методов станет побочной выгодой
   и вопрос пересматривается.
