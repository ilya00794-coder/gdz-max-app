## Bot API: рабочая конфигурация
- **Хост: `platform-api.max.ru`** (переопределяется `MAX_API_HOST`). Документация
  рекомендует `platform-api2.max.ru`, но его сертификат выпущен «Russian Trusted
  Sub CA» (Минцифры) и не проходит проверку с dev-машины. На проде с установленным
  корнем Минцифры можно переключиться на api2.
- Токен — **заголовком `Authorization`**; параметр URL `access_token` отвергается
  с `verify.token`.
- Лимит: 30 rps на всё API бота; при 429 читать `Retry-After`.

## Проверка подписки (проверено на живом API 28–29.08.2026)
- `GET /chats/{chatId}/members?user_ids=<id>`:
  - подписан → **200 + запись в members**;
  - не найден → **200 + пустой members** (не 404!);
  - 404 остаётся признаком неверного chatId, т.е. ошибкой конфигурации.
- Метод возвращает ОБЫЧНЫХ подписчиков канала (48 из 50 без флагов), не только
  админов. В записи ChatMember НЕТ поля статуса (member/left) — только
  is_owner/is_admin/is_bot; участие = присутствие в ответе.
- **НЕ проверено: существующий аккаунт, не подписанный на канал** (тест был на
  несуществующем id). Закрывается shadow-режимом на реальном трафике.
- Пагинация marker не проверена (канал < 100 подписчиков, одна страница).

## Gating (backend/src/subscription.js)
- `SUBSCRIPTION_GATING`: `off` (по умолчанию) / `shadow` (решение логируется,
  никто не блокируется) / `on` (not_subscribed → 403, ошибка → fail-open).
- Кэш: subscribed 15 мин, not_subscribed 60 сек, error не кэшируется; после 429 —
  backoff по Retry-After.
- Интерлок: `on` требует `STRICT_INIT_DATA=on`, иначе сервер не стартует —
  без подписи initData userId подделывается заголовком.
- Старт-проверка `GET /chats/{id}`: не 200 или type≠channel → громкая ошибка в лог
  (неверный chatId при fail-open молча открыл бы доступ всем).

## MAX Bridge / initData (webapp + middleware, проверено ранее)
- Скрипт st.max.ru/js/max-web-app.js создаёт window.WebApp ДАЖЕ вне MAX —
  признак настоящего клиента только непустой initData (фронт так и определяет режим).
- Подпись initData: secret = HMAC-SHA256("WebAppData", MAX_BOT_TOKEN), затем подпись
  отсортированных a→z параметров, склеенных \n. Сверено с реальной строкой с телефона.
- STRICT_INIT_DATA (off по умолчанию): on → 401 без валидной/свежей подписи.
  Локальные запросы отличаются НЕ по адресу (ngrok проксирует на 127.0.0.1),
  а по отсутствию X-Forwarded-For.
