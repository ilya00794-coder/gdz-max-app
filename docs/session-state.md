## Деплой-состояние по слоям (на момент записи)
- **Бэкенд**: локальный, жив (`curl localhost:3000/health`), запущен из HEAD.
  Запуск: `cd backend && nohup npm run start:env >> <лог> 2>&1 & disown` —
  ОБЯЗАТЕЛЬНО nohup+disown (фоновую задачу сессии однажды убила обвязка,
  прод лежал) и ОБЯЗАТЕЛЬНО `>>`, не `>` (перезапись дважды теряла данные).
  В процессе живут: HTTP API, long polling бота, алерты, часовой отчёт.
- **Туннель**: ngrok, https://whacking-ramble-womb.ngrok-free.dev
  (совпадает с webapp/config.js на Pages). Адрес одноразовый: при смене —
  config.js + коммит + scripts/deploy-pages.sh (+ до 10 мин CDN).
- **Фронт на Pages**: версия `2ca0c2c-31.08.1346` — чертежи целиком, экран
  подписки (скрыт до включения гейтинга). ЕДИНСТВЕННАЯ незадеплоенная
  фронт-мелочь: suggestedMode для handwritten_task (коммит 386b887) —
  по решению Ильи уедет со СЛЕДУЮЩИМ деплоем, отдельный не нужен.
- **БД**: Postgres localhost/gdz_max; verify_events расширена экономикой
  (input/output_tokens, cost_usd, cache_hit, user_hash, start_param);
  новая таблица incident_users (пострадавшие от сбоев — узкое ИСКЛЮЧЕНИЕ
  из политики «max_user_id не хранится», причина в schema.sql).
- **Бот** @id772408566819_bot («Домашка в МАХ», подтверждён GET /me):
  вайтлист MAX_ADMIN_USER_IDS=46536812 (Илья).

## Телеметрия: что теперь пишется (verify_events, source remote/canary/local)
- Экономика: input/output_tokens и cost_usd каждого запроса (сумма всех
  AI-вызовов: vision+solver+compare; прайс фиксируется при записи);
  кэш-хиты пишутся (cache_hit=true, cost 0) — слепое пятно закрыто.
- user_hash — НЕОБРАТИМЫЙ HMAC с солью USER_HASH_SALT из .env (решение
  Ильи): уникальные, новые/вернувшиеся. Личность не восстановима.
- start_param — метка поста (?startapp=post_YYYYMMDD), атрибуция приходов.
- 422-отказы: errorKind='refusal', reason-класс (no_task_found |
  low_confidence | unreadable_work); развилка выбора задачи —
  multiTask + 'multiple_tasks_choice' (не отказ).
- Осознанные упрощения (бэклог): стоимость сбойных запросов ≈ 0;
  сторож живого сервера не покрыт (мёртвый процесс не сообщит — автоподъём).

  медиана/максимум, приходы по меткам; первый отчёт дня — строка «Вчера».
  Порог: любое remote-событие часа; тишина = «никто не приходил».
- Посты: текст боту → превью → «Опубликовать» → пост в канал с кнопкой

## Рабочие правила проекта (нарушение = переделка)
1. СТОП-И-ОТЧЁТ после каждого шага; явное добро Ильи перед следующим.
2. Не выходить за рамки задачи молча; отступление — сказать явно.
3. СНАЧАЛА ФАКТЫ, КОДА НЕ ПИШИ — когда Илья просит разбор/диагностику.
4. Канарейка после каждого изменения, ОБЕ стороны; частичная — честно.
5. Проверять доставку как клиент: кэш без ?cb=, API — preflight с Origin.
6. Деплой фронта ТОЛЬКО scripts/deploy-pages.sh.
7. Канарейки к API — с заголовком X-Canary.
8. Ложный FALSE терпим, ложное verified — нет. Запреты прямые,
   требования — с условием применения.
9. Новый заголовок фронта = правка CORS allowedHeaders тем же коммитом.
10. Предупреждать Илью В МОМЕНТ деплоя фронта и перезапусков бэкенда.
11. Правка схемы solver = сначала проба грамматического бюджета
    (запас — единицы строковых полей; паттерн проб — бэклог).
12. catch-chat-id.js НЕ запускать при живом сервере (гонка за /updates).
