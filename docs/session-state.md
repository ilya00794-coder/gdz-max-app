## Правила организации кода (уборка кода, приняты 01.09.2026)
Куплены картой уборки этой недели; каждое — с багом-покупателем и проверкой.
Парные правила «реестр парных точек» и «новый фронт-модуль» живут
в project-handoff.md рядом с доставкой/CORS.

- **Дели по ответственностям, не по строкам.** Длина сама по себе не повод
  делить. Делим, только когда в файле ответственности, НЕ делящие изменяемое
  состояние. Длинный по одной теме файл не трогаем (verify_sympy.py —
  символьная математика, solver.js — схема+промпт); app.js делили не за 2305
  строк, а за то, что SVG-блок не делил состояние с остатком.
  Куплено: карта — app.js (рост накоплением, ~10 ответственностей) против
  verify_sympy.py/solver.js (длинные по существу).
  Проверка: кандидат на вынос — только кусок «данные→X без DOM/состояния»;
  рез через общее изменяемое состояние (state, текущий экран, очередь) — не
  делить.

- **Рефактор в проде — только под эталон.** Выносить/чистить в живом проде
  оправдано, лишь когда можно снять ПОБАЙТНЫЙ эталон до и сверить после, а
  вход/выход не меняется. Кусок с непроверяемым (webview, тач, сетевой поллер,
  гонки) не трогаем ради структуры — риск выше выгоды.
  Куплено: 01.09 SVG-блок был чистым → эталон снялся, регрессия побайтная;
  экранные/стрим-кластеры делят state, поллер botChannel неповторим канарейкой —
  сознательно не трогали.
  Проверка: «сниму эталон до и получу пустой diff после?» Нет эталона — это не
  уборка, а переписывание; откладывай в отдельный заход.

- **Уборка ≠ поведение: разные коммиты.** Структурная уборка (без смены
  поведения) и правка логики/формата — разные заходы со своей приёмкой.
  Уборочный коммит обязан давать тот же выход; меняется выход — это уже не
  уборка. ТРЕБОВАНИЕ (не рекомендация): уборочный коммит идёт ОТДЕЛЬНЫМ
  коммитом от коммита с поведением, даже если оба сделаны в один заход по
  времени — иначе при откате придётся выбирать между потерей уборки и
  потерей правки.
  Куплено: разделение 01.09 — вынос SVG отдельно от parseCandidateAnswer
  (смена формата solver↔verify): «при поломке не поймём, что сломало».
  Проверка: у уборочного коммита регрессия побайтная (пустой diff); непустой
  diff = баг выноса либо это была не уборка — разводи.
